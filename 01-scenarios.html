场景：独立开发者正在让 agent 改项目，看到方向不对，输入“先停手，只检查”。

Harness 从用户操作到结果
Codex 当前采样或工具结束 → 处理待收输入 → 后续模型请求调整方向；不能承诺正在执行的写入立刻停下。
OpenCode 消息先入箱 → 忙时处理 steer，空闲取一条 queue → 后续步骤采纳；仅入箱不等于开始。
pi / pi-durable 10 月普通 pi 在工具批后取 steer，结束前取 follow-up；durable 的持久输入队列另见恢复页，不能把普通内存队列当作落盘。
dsh steer 在下一步采纳并唤醒；followup 等下一轮；inject 只注入、不唤醒；接错入口会让用户以为没收到。
Hermes 工具批次结束 → 追加 user 消息 → 下一次模型调用看见纠正；已存工具结果不改。
OpenClaw embedded 在循环边界处理 pending；Codex 路线转交另一套 turn/start，排错先辨认路线。
Claude Code 【bundle】工具执行后取本 agent 的 next 消息；不能由流式显示推断实时停止工具。【bundle】
DeepAgents（1 月 Python） 预先配置 interrupt_on → 指定工具前进入人工审批 → 批准后续跑；这是审批断点，不能直接等同于任意时刻的 steer。

为什么重要： 已完成的写入不会因插话自动撤销。产品应分别显示“已收到”和“模型已采纳”，并统计从插话到采纳的时间。 查看技术细节与出处。
