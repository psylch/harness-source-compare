场景：独立开发者正在让 agent 改项目，看到方向不对，输入“先停手，只检查”。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 当前采样或工具结束 → 处理待收输入 → 后续模型请求调整方向；不能承诺正在执行的写入立刻停下。〔5〕〔7〕
OpenCode 消息先入箱 → 忙时处理 steer，空闲取一条 queue → 后续步骤采纳；仅入箱不等于开始。〔9〕
pi / pi-durable 10 月普通 pi 在工具批后取 steer，结束前取 follow-up；durable 的持久输入队列另见恢复页，不能把普通内存队列当作落盘。〔11〕
dsh steer 在下一步采纳并唤醒；followup 等下一轮；inject 只注入、不唤醒；接错入口会让用户以为没收到。〔13〕
Hermes 工具批次结束 → 追加 user 消息 → 下一次模型调用看见纠正；已存工具结果不改。〔15〕
OpenClaw embedded 在循环边界处理 pending；Codex 路线转交另一套 turn/start，排错先辨认路线。〔17〕
Claude Code 【bundle】工具执行后取本 agent 的 next 消息；不能由流式显示推断实时停止工具。〔19〕
DeepAgents（1 月 Python） 预先配置 interrupt_on → 指定工具前进入人工审批 → 批准后续跑；这是审批断点，不能直接等同于任意时刻的 steer。deepagents@c177c9f:libs/deepagents/deepagents/graph.py#L121-L131

为什么重要： 已完成的写入不会因插话自动撤销。产品应分别显示“已收到”和“模型已采纳”，并统计从插话到采纳的时间。

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

共识

  • 骨架相同： 把可执行调用和面向人的回答分开，工具结果作为下一次模型请求的输入。工具执行是宿主的副作用，所以工具边界也是取消、审批、恢复能插入的位置〔1〕〔2〕〔3〕。
  • “流式”不等于“每个 token 都能重新决策”： pi 把 text/thinking/toolcall delta 作为事件发出，但要等工具批次完成才读下一批 steering；Codex 在 sampling 或工具完成后才处理异步 hooks 和 pending input〔4〕〔5〕。

术语：本系列把一次 provider 请求叫 step，把从用户输入开始、可能包含多个 step 的工作段叫 turn/run。各库的 turn_end 不一定指同一个边界〔1〕〔6〕。

关键差异

Harness step、停止与插话 轮数上限与重试默认
Codex run_turn 循环 sampling；模型调用工具续轮或有 pending input 都会继续；空闲时还要过 Stop hooks，hook 可以带提示词要求继续；steer 在后续 step 被 drain〔7〕 loop 内未确认统一的数值 max-steps。stream retries 5、request retries 4，可分别配置，上限 100；特性开启时部分连接失败可以无界重试，等待 5s→倍增→60s；stream 重试耗尽后可从 WebSocket 降到 HTTPS 并重置计数〔8〕
OpenCode 每次 drain 都重载 durable history，runStep 发一次显式 llm.stream；prompt 默认 steer，先 admit 再 wake，resume:false 只入箱；忙时只投 steer，空闲时取一条 queue〔9〕 只有配置了 agent.info.steps 才限步；到上限的最后一步保留 tool schema、toolChoice=none 并要求总结。普通重试最多 10 次，指数退避从 2s 起、单次上限 10s、带 jitter；Retry-After 最多按 15min 作为最小等待；transport timeout 另计，最多 3 次〔10〕
pi 内层循环处理工具和 steering，外层在本该结束时取 follow-up；两种队列默认 one-at-a-time；finishTurn 可以 end/continue；输出因 length 截断的调用参数全部按失败处理，不执行〔11〕 核心 loop 未确认数值 max-steps。coding-agent 默认 retry 3、base 2000ms、指数 base*2^(attempt-1)、上限 60000ms；上下文溢出单独处理，只做一次 compact-and-retry〔12〕
dsh turn/start→pre-step→step/start→prepare→stream→assistant/message→tools→step/end。steer=next-step 并唤醒，followup=next-turn 并唤醒，inject=next-step 但不唤醒；next-step 整批取，next-turn 最多取一条〔13〕 主 loop 的统一 maxSteps 未确认，pre-step 可以拒绝继续。可选 retry 插件默认 normal：5 retries、500ms 起、上限 10000ms、jitter 0.1〔14〕
Hermes prepare→assemble→preflight→API attempts→normalize→工具 round 或文本完成；/steer 在工具 batch 之后追加新的 user 消息，不改已存的 tool result〔15〕 默认 max_iterations=sys.maxsize。agent.api_max_retries 默认 3 次 attempt（含首次，设 1 就是只试一次）；fallback 后自动恢复周期默认 5；退避 base 2s、上限 60s〔16〕
OpenClaw 自有 agent-core 的工具 / pending-message loop 在边界处理取消；切到 AgentHarnessV2 的 Codex 路线后实际发的是 turn/start〔17〕 embedded session retry 默认 3、base 2000ms，不是所有 provider/fallback 的总次数〔18〕
Claude Code【bundle】 async generator while(true)；没有工具调用时，仍可能因输出耗尽、thinking-only 或 Stop hook 继续；工具执行后提取 priority=next 且属于本 agent 的消息；Stop hook 连续阻止默认上限 8〔19〕 只有传入 truthy 的 maxTurns 才检查。普通 retry 默认 10，CLAUDE_CODE_MAX_RETRIES 最多 15；退避 min(500*2^(attempt-1),32000) 加 0–25% jitter；persistent 分支另行等待〔20〕

provider 抽象也有差异： - Codex： WireApi 在此快照只接受 responses，reasoning 要经过 resolve_reasoning_effort 映射〔21〕。 - pi： Anthropic adapter 按模型选 disabled、adaptive+effort 或 enabled+budget_tokens，最后一种未传值时默认 1024〔22〕。 - dsh： 它用的 pi-ai adapter 显式设 maxRetries:0，避免 SDK 重试和 harness 重试叠加〔23〕。

对不同用户的影响（基于控制流的情景推演）

  • 长任务重度用户、IDE 用户：插话不是撤销。 工具批次正在改文件时，用户说“先停，只检查”。pi/Hermes 的 steer 一般在批次边界之后才影响下一次请求，已经写入的文件不会回滚〔24〕。
  • 成本敏感用户：attempt、retry、recovery cycle 是三个不同的计数器。 同样配成“3”，Hermes 包含首次调用，pi 指失败后的额外尝试，Codex 还有传输降级后的计数重置〔16〕〔25〕〔8〕。
  • 非工程师：“再加一页预算”被发了两次。 dsh 的 inject 不唤醒 agent，OpenCode resume:false 只入箱。集成方如果把“已收到”写成“已开始”，用户就容易重复发送〔13〕〔9〕。
  • 企业团队： OpenClaw 切到 Codex harness 后，审批、steer、恢复可能横跨 Gateway 和 Codex app-server。排查问题时要先记录实际走的 harness 路线〔17〕〔18〕。

面试可讲的点

  1. 把“实时”拆成三个问题来问：画面多久刷新一次？用户消息多久被模型看到？正在跑的工具会不会被取消？
  2. 输入确认的状态机至少要有 4 个状态：已排队 / 下一步采纳 / 下一 turn 采纳 / 已停止当前执行。
  3. 重试默认值不能横向直接比，要先统一口径：是否包含首次调用、是按 stream 还是按 request 计、降级后是否重置。
