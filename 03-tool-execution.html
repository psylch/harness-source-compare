03 · 工具执行：调度、并发、编辑与错误回填

← 02 · Agent loop：step、插话与重试 · 总览 · 04 · 审批与 OS 隔离：两道不同的边界 →

场景：维护大型仓库的开发者让 agent 同时读 20 个文件，并修改其中一个文件。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 安全调用共享读锁 → 其他调用取独占写锁 → 有冲突时等待；64 是进程上限，不是 64 个工具都并行。〔4〕〔8〕
OpenCode 完整调用先持久化 → 启动执行分支 → 最后等待汇合；此处未确认路径冲突锁。〔14〕
pi / pi-durable 普通 pi 默认并行 → 任一工具标 sequential 就整批串行；edit/write 同路径排队只保护本进程。durable 的提交规则另见专页。〔10〕
dsh 先检查工具是否显式声明并发安全 → 安全的进入默认 10 个槽位的池 → 其他独占执行。〔12〕
Hermes 先按路径读写冲突分组 → 安全区段最多 8 个 worker → 冲突写入形成等待屏障。〔6〕〔16〕
OpenClaw 默认并行执行 → 按调用原序提交结果；结果有序不等于共享文件无冲突。〔7〕〔18〕
Claude Code 【bundle】连续安全调用成组 → 默认最多 10 个并行 → 非安全调用隔开组。〔3〕
DeepAgents（1 月 Python） 工具交给 LangChain create_agent 执行；本层源码未给出可核实的全局并发数和同路径锁，不能承诺 20 个读都并行。deepagents@c177c9f:libs/deepagents/deepagents/graph.py#L239-L251

为什么重要： 等待时间取决于并发规则；是否误读旧内容或互相覆盖取决于冲突控制。并发数不能单独代表可靠性。

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

共识

  • 五段流水线： 工具调用普遍经过声明→校验→授权/拦截→执行→模型可见结果。模型输出不是可信的宿主函数调用，所以参数错误或被拒绝时要变成模型能理解的反馈，不能静默丢掉〔1〕〔2〕〔3〕。

  • “支持并行”都带顺序约束：

    • Codex：读写锁；
    • pi：Promise.all 按调用原序返回；
    • Hermes：划出带串行屏障的区段；
    • OpenClaw：区分“执行完成”和“按源顺序提交”。

    并发耗时、结果排序、文件冲突控制是三个不同的维度〔4〕〔5〕〔6〕〔7〕。

关键差异

Harness 调度与并发 编辑与错误回填
Codex tool executor 默认不并行，exec_command 明确允许并行；parallel-safe 调用共享读锁，其余独占写锁。64 是存活 unified-exec 进程上限，不是工具线程数〔8〕 freeform apply_patch 的匹配逐级放宽：exact→trim_end→两端 trim→Unicode 标点归一化。普通工具错误包装成 failure response，只有 Fatal 才向上抛并终止〔9〕
pi coding-agent 默认 parallel；批次里只要有一个工具声明 executionMode=sequential，整批串行。edit/write 对同一路径排队，这是进程内锁，管不到其他 shell 或进程〔10〕 edit 先 exact，再做归一化模糊匹配；也可以用 write 重写整个文件。durable 版本在 hook 之后重新校验，被拒绝的调用写成错误结果〔11〕
dsh 工具必须 isConcurrencySafe(args)===true 才进并行池，缺省、异常或无效参数一律走 exclusive barrier；默认并发 10，agent-loop.maxParallelToolCalls 可改〔12〕 edit 是 literal 的 old_string/new_string，replace_all=false，要求唯一匹配；执行前先记录 fs/edit-intent 和 observed version，再原子 editText。超时返回 isError 和 TOOL_TIMEOUT，未启动就被取消的调用补一条 synthetic result〔13〕
OpenCode 完整 tool-call 的 durable publication 完成后，forkScoped 执行，最后 join；这个位置没看到固定上限或 safe/exclusive 白名单〔14〕 先 exact，再做标点/空格归一化并忽略行尾空白；保留 LF/CRLF；多处匹配且未设 replaceAll 时拒绝。用户拒绝时附带的 feedback 可以形成 CorrectedError〔15〕
Hermes parallel-safe 区段内并发，同路径 reader 之间可以重叠，writer 冲突形成屏障；worker 上限 8，image_generate 有更小的专用限额〔6〕〔16〕 9 级 fallback 链：exact→line_trimmed→whitespace_normalized→indentation_flexible→escape_normalized→trimmed_boundary→unicode_normalized→block_anchor→context_aware；出现多个近似匹配时，即使 replace_all 也拒绝〔17〕
OpenClaw embedded 默认 parallel，按源顺序提交结果；该层统一上限未确认〔7〕〔18〕 先做 NFKC、trimEnd 和引号/破折号/空格归一化再找精确片段，用 grapheme source map 映射回原文，拒绝不安全的边界〔19〕
Claude Code【bundle】 连续的 concurrency-safe 调用分组并行，默认上限 10，可用正数 CLAUDE_CODE_MAX_TOOL_USE_CONCURRENCY 覆盖〔3〕 Edit 使用 old_string/new_string/replace_all=false，内容相同、找不到、未允许的多处匹配都会拒绝，并尝试恢复 Unicode escape；权限 handler 改写 input 后重新校验 schema，不合法时返回 tool_result 错误〔20〕

schema 声明语言也不同，影响的是扩展作者拿到的静态类型和报错时机： - pi：TypeBox TSchema，可声明 outputSchema； - Hermes：JSON Schema dict，替换内置工具需要显式 override； - OpenClaw：exec 参数用 Type.Object 声明〔21〕。

对不同用户的影响（基于控制流的情景推演）

  • 长任务用户： 模型同时发出“读 A、读 B、跑测试”。Codex 按锁的类型决定能否并发；pi 只要测试工具声明了 sequential 就整批串行；Hermes 看路径是否冲突。wall time 和文件竞争风险都会不同〔4〕〔10〕〔6〕。
  • 扩展作者： 自定义工具没声明并发安全时，dsh 默认把它当 exclusive，pi 默认并行。同一个工具从一个 harness 迁到另一个，并发语义会变〔12〕〔10〕。
  • IDE 用户： “fuzzy edit”不是一种东西。Hermes 9 级链、OpenClaw 的 NFKC 加 source map、dsh 的 literal 唯一匹配，在格式化差异下成功率和误改风险都不同〔17〕〔19〕〔13〕。

面试可讲的点

  1. 并行要拆成三个问题：谁有资格并行（opt-in 还是 opt-out）？冲突域按什么划（锁、路径、整批）？结果按什么顺序提交？
  2. “编辑失败率”是可以直接度量的 harness 指标，可以按匹配级别埋点，看最终是哪一级 fallback 成功的。
  3. 错误要“回填给模型”还是“终止 turn”，决定了 agent 能否自我纠正。Codex 只有 Fatal 才终止〔9〕。
