场景：企业员工在笔记本上批准 agent 清理目录；命令里包含 rm 和网络下载。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 先走审批配置 → Linux 进程进入 bwrap/seccomp 限制；macOS、Windows 是各自的实现。〔1〕〔4〕〔5〕
OpenCode 匹配 action/resource 规则 → 未匹配则询问 → 本地 spawner 执行；默认 OS 隔离未确认。〔12〕〔13〕
pi 扩展可以拒绝调用 → 默认 bash 直接启动本机进程；放行后不能假定有 OS 沙箱。〔2〕〔8〕
dsh 按 preset 审批 → 平台 runner 隔离；申请放宽而审批服务缺失时拒绝执行。〔6〕〔7〕
Hermes 审批或 middleware 拦截 → 默认 local 后端运行；有其他后端不代表当前已隔离。〔9〕〔10〕
OpenClaw 按更严格的审批策略判断 → sandbox 默认关闭；启用后默认 docker，须核对配置。〔3〕〔11〕
Claude Code 【文档】规则可限制命令、路径、域名；启用的沙箱按 macOS/Linux 分支，原生 Windows 不适用该沙箱。〔15〕〔16〕
DeepAgents（1 月 Python） 默认 StateBackend 是状态里的虚拟文件 → execute 需要支持 SandboxBackendProtocol 的后端，否则报错；协议名不证明自定义工具受到 OS 隔离。deepagents@c177c9f:libs/deepagents/deepagents/graph.py#L121-L131；deepagents@c177c9f:libs/deepagents/deepagents/graph.py#L169-L169

为什么重要： 弹窗决定是否放行，操作系统隔离决定放行之后能碰到什么。要按实际平台和后端验收删除范围与网络访问。

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

共识

  • 都有审批层，但审批不是一个布尔值： 谁来批、能批到什么粒度、批完能否改参数，各家都不同。
  • 审批 ≠ 隔离： “允许运行 npm”说明不了这个进程能不能读到宿主上的密钥。隔离要看 OS 级的文件系统和系统调用限制〔1〕〔2〕〔3〕。

关键差异

Harness 审批模型 OS 隔离（默认与平台分支）
Codex 审批枚举 untrusted/on-request/granular/never，on-failure 已是 on-request 的 alias〔4〕 Linux 当前路线是 bubblewrap + seccomp/no_new_privs；macOS 走 Seatbelt，Windows 有 restricted/elevated 两种 backend〔1〕〔5〕
dsh sandbox-policy 组件默认 read-only；用户 preset 提供 workspace-write+ask、full-access+never 两种。申请更宽的 sandbox_permissions 需要审批，缺少审批服务时 fail-closed〔6〕 Linux runner 链 bwrap→Landlock，macOS Seatbelt，Windows ACL〔7〕
pi coding-agent CLI hook 可以 block 或改参数〔8〕 默认 shell 实现直接在本机 spawn 进程，不是 OS 沙箱；可替换 operations/spawnHook〔2〕
Hermes CLI callback 提供 once/session/always/deny/timeout/cancelled，Gateway 另有 approve/deny；middleware/plugin 的 block 转成 tool_error，ACP 编辑审批在其后〔9〕 默认 terminal backend=local；支持其他 backend，但不能推出“默认隔离”〔10〕
OpenClaw exec 的 ask 默认 off，但会和审批 policy 取更严格的交集；先向 Gateway 注册 exec.approval.request 拿到服务端 ID 再报告 pending，避免审批和注册之间的竞态〔11〕 sandbox 默认 off；启用后 backend 默认 docker、workspaceAccess none〔3〕
OpenCode 权限按 action/resource 通配符匹配，最后一条匹配规则生效，没有匹配就 ask；选 always 会存成 project 范围的规则〔12〕 所核的本地 shell 只有 AST/resource 审批和 spawner，默认 OS 沙箱未确认〔13〕
Claude Code 【bundle】schema 描述里有 default/acceptEdits/bypassPermissions/plan/dontAsk/auto 几种模式，但不能据此认定 auto 是 2.1.197 的默认值；SDK 路径向宿主发 can_use_tool 控制请求〔14〕。【文档】规则可以细到 Bash 命令、Read 路径、WebFetch 域名〔15〕 【文档】macOS 用 Seatbelt，Linux/WSL2 用 bubblewrap+socat，原生 Windows 不支持这套沙箱〔16〕

对不同用户的影响（基于控制流的情景推演）

  • 企业安全团队： 比较部署方案时，要记录实际启用的 backend 和 profile，不能给产品贴一个永久的“有沙箱”标签。比如 Codex 在 Linux 上有 OS 级限制，而 pi 默认本地 spawn、OpenClaw sandbox 默认 off〔1〕〔2〕〔3〕。
  • Windows 用户： 隔离能力按平台分支。Claude 文档明确写了原生 Windows 不支持这套沙箱，Codex 和 dsh 在 Windows 上走的是另一套 backend〔16〕〔5〕〔7〕。
  • 非工程师： 按 project 范围存的“always”规则（OpenCode）和按会话生效的“session”授权（Hermes），持续时间不同。要让用户能看到当前有哪些放行规则在生效〔12〕〔9〕。

面试可讲的点

  1. 拆成两个指标分别度量：审批负担（每任务的弹窗次数、误批准率）和爆炸半径（批准之后进程能接触到的资源）。
  2. 缺少审批服务时是 fail-closed 还是 fail-open（dsh 是 fail-closed），本身就是一个产品决策点〔6〕。
  3. 审批 UI 的竞态问题：OpenClaw 先注册再报告 pending 的做法，是可以举出来的一个细节〔11〕。
