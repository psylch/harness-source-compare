场景：负责发布的工程师跑测试，工具返回 5 MB 日志：开头是配置，中段是根因，结尾是失败汇总。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 进程缓冲保留头尾 → 返回受默认 10000 估算 token 预算约束 → 中段可能不可见。〔2〕〔5〕
OpenCode shell 留尾，通用工具留头 → 超限全文保存 → 可继续读取，默认保留 7 天。〔16〕
pi bash 超过 2000 行或 50KiB 留尾 → 全文存临时文件 → 模型先看到末尾汇总。〔1〕〔7〕
dsh bash 字节限制、spill 外置、历史裁剪是不同层 → 外置结果保留头尾 → 不能把某一层阈值当全部预算。〔13〕〔14〕
Hermes 按 50000 字符裁剪 → 头 40% / 尾 60% → 启动配置和最终汇总都可能留下。〔3〕
OpenClaw 按模型窗口选 16000/32000/64000 字符硬上限 → 大窗口能看到更多，但不保证根因仍在。〔10〕

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

共识

  • 长输出都会截断，全文多数另存。 但下面四个量不能互换：模型可见截断、内部缓冲、等多久返回、进程活多久。
  • 截断策略直接决定模型“看见了什么”。 留头、留尾和头尾都留，对同一份日志会给出不同的可见内容〔1〕〔2〕〔3〕〔4〕。

关键差异

Harness / 路线 模型可见输出（默认） shell 生命周期 / 超时
Codex unified exec 默认返回预算 10000 估算 tokens，可由参数 max_output_tokens 覆盖；进程缓冲另限 1024*1024 bytes，头尾各半〔2〕〔5〕 interactive 模式可以保留进程供 write_stdin 使用；默认 exec yield 10000ms，范围 clamp 到 250..30000ms，到期不会杀进程。OneShot 默认 timeout 10000ms〔6〕
pi bash/read 通用阈值 2000 行或 50*1024 bytes；bash 留尾并把全文存到临时文件，read 留头〔1〕〔7〕 每次调用 spawn 一个新 shell；没有默认 timeout；传入值必须是有限正数，换算成毫秒后不能超过 2147483647〔8〕
Hermes terminal tool_output.max_bytes 默认 50000，但实际按字符切；头 40% / 尾 60%。read_file 默认 2000 行、单行 2000 字符〔3〕 LocalEnvironment 默认 persistent=True，但每次 execute 都是新 bash，靠环境快照和 cwd marker 保留状态；terminal 默认 180s，外层 batch 默认 420s〔9〕
OpenClaw embedded live tool result 的硬上限随上下文窗口变化：16000/32000/64000 chars，分界点 100000/200000 tokens，再和 context*0.3*4 取最小值；exec 聚合缓冲默认 200000 chars〔10〕 exec 默认 1800s；后台 yield 默认 10000ms，可 clamp 到 10..120000ms。native Codex 路线不适用这些值〔11〕
Claude Code【bundle】 Bash 默认 30000 字符，上限 150000，留头；TaskOutput 默认 32000，上限 160000，留尾〔4〕 Bash 默认 120000ms，最大值为 max(600000, default)〔12〕
dsh bash-local 默认 64000 bytes；base 装配的 spill 阈值为 12500 estimated tokens，全文外置、头尾保留；另有 tool-result-pruner，超过 8192 code points 时按 4096 头 / 1024 尾裁掉中段〔13〕〔14〕 普通 bash 每次新 subprocess，默认 120000ms、单次上限 600000ms，超时可以转后台；另有 persistent PTY，send 默认 30000ms〔15〕
OpenCode 通用默认 2000 行 / 50KiB 留头，shell 用同样预算但留尾；全文默认保存 7 天〔16〕 每次 create 一个新进程；前台默认 2×60×1000ms，后台设 0 表示无 timeout〔17〕

对不同用户的影响（基于控制流的情景推演）

  • 长任务用户： 一份测试日志，开头是配置，中间是详细失败，结尾是汇总。

    • pi bash 留尾，容易看到最终统计；
    • Codex 和 Hermes 头尾都留，还能看到启动配置；
    • Claude Bash 留头，中段和尾部要靠后续读取。

    模型“忘了报错”，有时是截断策略造成的〔7〕〔2〕〔3〕〔4〕。

  • 非工程师、IDE 用户： 两分钟没返回，不一定是挂了。Codex 的 yield 到期可能只返回一个 session handle，pi 没传 timeout 时会一直等。UI 要区分“后台仍在运行”和“已超时终止”，否则用户重复点击会重复启动工作〔6〕〔8〕。

  • 成本敏感用户： OpenClaw 的上限随窗口变化，同一工具换个大窗口模型，可见输出量最多可以差 4 倍（16000 vs 64000 chars）〔10〕。

面试可讲的点

  1. 截断方向（头 / 尾 / 头尾）和单位（行 / bytes / 字符 / tokens）是可以 A/B 的参数，主指标可以选“失败信息是否在模型可见范围内”。
  2. yield ≠ timeout ≠ 进程寿命，状态 UI 要把这三件事区分开。
  3. Hermes 把字段命名为 max_bytes 实际却按字符计，可以作为“配置语义一致性”的例子来讲〔3〕。
