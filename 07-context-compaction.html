场景：分析师在 200K 窗口模型上连续研究 3 小时，还要保留一小时前找到的原始证据。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 默认自动压缩上限为 180000 token → 按 provider 走本地或远程压缩 → 不能把两条路线视为同一种摘要。〔4〕〔5〕
OpenCode 按 20000 buffer 算出 180000 阈值 → 保留近期目标 15000 token → 较早证据进入摘要。〔8〕
pi / pi-durable CLI 超过 183616 触发；durable 可在 150848 提前后台摘要 → 阻塞线仍为 183616；近期目标 20000。〔6〕〔7〕
dsh 取 80% 窗口与扣除输出预留、65536 后的较小值 → 保留近期与工具配对；输出预算未知不能给单一数值。〔9〕
Hermes 200K 属小窗口分支，比例至少 0.75 → 再考虑输出预算和下限 → 保护头 3、尾 20 条。〔10〕
OpenClaw 按 reserve 公式留空间 → 到线压缩；deterministic 策略可直接删除旧消息并标记，不生成摘要。〔11〕〔12〕
Claude Code 【bundle】输出预算至少 20000 时，触发点 167000 → 连续压缩另有保护；保留策略未在本页确认。〔13〕
DeepAgents（1 月 Python / JS） Python 有模型窗口 profile 时以 85% 触发、保留 10%；缺少 profile 则 170000 / 6 条。JS 当时固定 170000 / 6 条，不能混用两者公式。deepagents@c177c9f:libs/deepagents/deepagents/graph.py#L144-L162；deepagentsjs@6b912ab:libs/deepagents/src/agent.ts#L187-L192

为什么重要： 达到阈值会影响哪些原文仍在下一次请求里。摘要能延续任务，却可能损失细节；重要证据应能从文件重新读取。

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

（prompt 拼装顺序、指令发现规则和缓存前缀见 06 · Prompt / 上下文拼装顺序。）

共识

  • 计量方式基本相同： 不是“有没有 tokenizer”的二选一，而是最近一次 provider usage 加上新增内容的本地估算。精确的只有已经返回的那次请求的 usage〔1〕〔2〕〔3〕。
  • 空间不足时摘要较早部分、保留近期原文。 差异在于什么时候触发、保留多少、保护哪些消息。

关键差异

Harness 触发公式（W=窗口） 保留与丢弃
Codex auto_compact 上限默认 context_window×9/10，显式配置的 limit 与它取最小值；95% 是“可用窗口”的 headroom 概念，不是 auto-compact 阈值〔4〕 按 provider 能力选 remote V2 或 local 路径；local 路径用 user messages 加 summary 重建，user 消息保留预算 20000 tokens。remote 的内容不能假定和本地摘要等同〔5〕
pi coding-agent tokens > W−16384 触发；溢出时做一次 compact-and-retry〔6〕 近期保留目标 20000 tokens，摘要较早部分〔6〕
pi-durable 后台摘要在 W−16384−32768 提前开始，阻塞线仍是 W−16384〔7〕 同上；前台和后台两条线分开
OpenCode buffer=max(floor(0.1W), W≥32000 时 16000，否则 0)，可显式覆盖〔8〕 保留近期 15000 tokens；摘要排除 AGENTS 和环境信息；支持 native compaction，摘要缩减目标依次为 0.7/0.5/0.35〔8〕
dsh floor(min(0.8W, W−reservedCompletion−65536))〔9〕 近期目标 0.16×(W−reservedCompletion)；保留 system 头和近期尾，不切断 tool 配对；预步压缩失败可以 warn 后继续〔9〕
Hermes 基础阈值 0.50；窗口 <512000 时提高到至少 0.75；先扣 max_tokens，floor 取 64000，floor 过大时有 0.85 护栏〔10〕 保护头部 3 条、尾部 20 条消息；summary_target_ratio 0.20〔10〕
OpenClaw embedded reserve=min(max(current,20000), W×0.25)，比较 tokens > W−reserve〔11〕 session 基础 keepRecent 20000；summaryOutputPolicy=deterministic 时走 compactWithoutSummary，保留近期原文，并标注有多少旧消息未经摘要被删除〔11〕〔12〕
Claude Code【bundle】 设 G=W−min(modelMaxOutput,20000)，默认触发点 G−13000；合法的百分比 override 为 min(floor(G×pct/100), G−13000)；window 覆盖值检查范围 100000..1000000；连续短间隔压缩有 breaker〔13〕 —

代入 W=200K（纯算术，只用于对比）： - pi：200000−16384=183616； - OpenCode：200000−20000=180000； - Codex：上限 180000； - Claude（maxOutput≥20000 时）：200000−20000−13000=167000。

不调用模型的预处理层： dsh 的 tool-result-pruner（超过 8192 code points 时按 4096 头 / 1024 尾裁剪）和 spill，与对话摘要是不同的处理层〔14〕。

计量细节： - dsh：ceil(chars/4) 加 block/role 开销； - OpenCode：round(chars/4)； - Hermes：CJK 和 ASCII 分别估算〔15〕。

图片： - pi：默认缩到 2000×2000，base64 预算 4.5MiB； - OpenCode：历史图片总量超过 25MiB 后裁到 15MiB，最旧的先换成诊断替身； - OpenClaw：默认 1200px / 5MiB； - Claude【bundle】：JPEG quality 依次 80/60/40/20； - Hermes：JPEG 依次 85/70/50，最多缩 5 轮〔16〕。

对不同用户的影响（基于控制流的情景推演）

  • 长任务重度用户： 两小时的重构，第 90 分钟触发压缩。pi 以近期约 20000 tokens 为保留目标；Codex 走本地摘要还是 remote 取决于 provider 能力；pi-durable 可能提前 32768 tokens 就开始后台摘要。用户真正关心的是“刚发现的失败证据还能不能原样读到”〔17〕〔5〕〔7〕。
  • 非工程师： 上传一张超长设计图，自动 resize 可能让细小的文字看不清。需要裁剪或局部重读来确认，不能假设模型看到了原始像素〔16〕。
  • 成本敏感用户： Hermes 在小窗口模型上至少到 0.75 才压缩，大窗口模型上 0.50 就压缩，同一会话换模型后压缩频率会变〔10〕。

面试可讲的点

  1. 可预期性比聪明更重要：用户要知道什么时候压缩、压掉了什么、能不能撤回。社区里 Claude Code 空闲压缩静默丢上下文的 issue 就是反例，见 18 · 社区痛点。
  2. 可以 A/B 的参数：触发阈值、近期保留预算、是否保护 tool 配对、摘要是否排除指令文件。主指标选“压缩后任务完成率”，护栏选“压缩后重复读取次数”。
  3. 不要用“接近上限就总结”一句话概括，各家公式差异在 200K 窗口下就有 1.6 万以上 token 的触发点差距。
