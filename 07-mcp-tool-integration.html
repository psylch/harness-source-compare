07 · MCP 与工具接入：加载、进入上下文、工具多了怎么办

← 06 · 上下文计量与压缩：触发公式、保留什么、图片与缓存 · 总览 · 08 · 记忆与技能：存下来、选出来、再注入是三件事 →

（扩展的权限边界见 12，工具声明在 prompt 中的位置见 05。）

共识

  • 传输方式： 都支持 stdio 和 Streamable HTTP，Hermes 和 OpenClaw 还支持 SSE〔1〕〔2〕〔3〕〔4〕〔5〕〔6〕。
  • 命名： 都会给工具名加 server 前缀并清理字符，超长或冲突时加 hash 或序号；模型看到的名字和真正发给 server 的原名是分开存的〔7〕〔8〕〔9〕〔10〕〔11〕。

  • 工具多了不再全量声明，这一点已经趋同。 常见做法：

    • 先给模型一个简短目录，或只给命名空间；
    • 模型通过 tool_search 或代码里的 search() 找到工具；
    • 找到后再声明 schema，或者走 describe/call 桥。

    各家的分歧在于触发条件，以及“加载后怎么调用”〔12〕〔13〕〔14〕〔15〕〔16〕〔17〕。

  • MCP 不会获得宿主 system/loop/UI 的权限， 但多数实现会在调用前走宿主的权限检查〔18〕〔19〕。

关键差异

加载与传输

Harness 配置与传输 默认超时
Codex mcp_servers，每个 server 可设 startup_timeout_sec、tool_timeout_sec、enabled_tools/disabled_tools、default_tools_approval_mode；分 stdio 和 Streamable HTTP 两种〔1〕 启动 30s，工具调用 300s〔1〕
OpenCode 配置在 mcp.servers，全局 mcp.timeout 会被 server 自己的设置覆盖；type: local 用 command 数组启动，远端用 StreamableHTTP〔2〕 启动和目录各 30,000ms，执行 43,200,000ms（12 小时）〔2〕
pi coding-agent agentDir 下的 mcp.json；项目里的 .pi/mcp.json 要等项目被信任后才读取；有 url 用 StreamableHttp，否则用 Stdio〔3〕 request 60s；首次 prompt 只等待有 direct 工具的 server，最多 10,000ms，其他 server 后台连接〔3〕〔20〕
dsh mcp-client 是 Cordis 插件，每个实例对应一个 server，多个实例写在 cordis.yml 里；failOnStartupError 默认 false，连不上就进入重连循环〔4〕 toolCallTimeoutMs 60,000ms〔4〕
Hermes config.yaml 的 mcp_servers，支持 ${VAR} 展开；HTTP 默认 Streamable，必要时回退 SSE；lazy: true 时首次使用才连接（默认 false）〔5〕〔21〕 连接 60s，工具调用 300s〔5〕
OpenClaw servers 是 name→config 映射，支持 stdio、sse、streamable-http〔6〕 连接 30,000ms，请求 60,000ms〔6〕
Claude Code 【文档】local/user 级配置在 ~/.claude.json，project 级在 .mcp.json，键是 mcpServers；交互会话使用 project MCP 前需要用户批准〔22〕 【bundle】MCP_TIMEOUT 默认 30,000ms；MCP_CONNECT_TIMEOUT_MS 默认 5,000ms；工具调用默认 100,000,000ms，最终 clamp 到 [1000, 2147483647]〔23〕

进入上下文：命名与 schema

Harness 命名规则 description / schema 处理
Codex 模型可见的 namespace/name 和原始 server/tool 名分开保存；名字会清理，必要时加 hash，上限 128 bytes；prefix_mcp_tool_names 控制是否加 mcp__ 前缀，可以按 server 豁免〔7〕 普通 MCP 工具的 description 不截断；agent-plugin 专用转换限 1,000 UTF-8 bytes；缺失的 properties 补成空对象〔24〕
OpenCode namespace 清理到 [A-Za-z0-9_-]；权限 action 是 server_tool〔8〕 保留 description；inputSchema 缺失时补 object〔8〕
pi coding-agent mcp__server__tool，非 [A-Za-z0-9_] 的字符换成 _，超长或冲突加 8 位 SHA-256 后缀〔9〕 补 type:object 和缺失的 properties〔9〕
dsh mcp__serverName__rawName，最多 64 字符，有损清理时加 12 hex 后缀；真正调用时用原名〔10〕 description、inputSchema、outputSchema 原样交给工具定义，序列化时带 defer_loading 字段〔25〕
Hermes mcp__<server>__<tool>，最多 64 字符，超长加 8 hex hash〔11〕 去掉 Unicode tags；definitions 转成 $defs，处理 nullable union，修复对象结构〔11〕
OpenClaw server__tool（没有 mcp__ 前缀），全名不超过 64，冲突时加 -2、-3〔26〕 metadata 截到 1,200 UTF-16 units〔26〕

工具很多时怎么办（延迟加载、检索、codemode）

Harness 触发条件 加载前模型看到什么 → 加载后怎么调用
Codex 源码注释写明 tool search “总是启用”，并且搜索可用时 MCP 工具总是 deferred，没有数量阈值；旧的 tool_search feature flag 已经是 no-op〔12〕 搜索用 BM25，命中的工具在下一次模型调用时提供；CodeMode 路径把 direct 和 deferred 工具分开收集〔27〕
OpenCode 由配置和权限决定：codemode:false 的工具直接声明，其余放进 codemode 目录，和工具数量无关〔13〕 内联目录预算 2,000（按 4 字符 ≈ 1 token 计），description 只取首行、最多 120 字符；目录放不下时，提示模型在 execute 里调用 search(...)〔28〕
pi coding-agent MCP exposure 默认 codemode，还有 deferred / direct / hidden；autoEnableCodemode 默认 true；内置的 tool_search 初始不激活，要显式启用〔14〕 codemode 只列 server 命名空间，脚本里用 searchTools() 找工具；deferred 工具经 tool_search（BM25，默认 8 项）加入 active set，下一轮直接声明〔14〕〔29〕
pi-durable tool_search 是独立的 extension，候选范围是 agent 的 deferred 工具〔30〕 通过 control.addTools 加入工具，在分支上一直保留，压缩后也保留；默认 8 项〔30〕
dsh 配置 mode 二选一：native（默认）/ ptc，不按工具数自动切换〔15〕 native 发送可见的 schema；ptc 只声明 run_code，加上一份按可见工具稳定排序生成的 SDK 说明〔15〕
Hermes tools.tool_search 默认 auto，目前等同 on：只要有可 deferred 的工具就激活〔16〕 原生工具数组换成 tool_search / tool_describe / tool_call 三个桥接工具；目录预算为 min(4000 tokens, context×5%)，超预算时从“名称+短描述”退到“只有名称”再退到“分组”；默认搜索 5 项，上限 25〔16〕〔31〕
OpenClaw tools.toolSearch 没设置时默认启用，mode=tools（另一选项是 directory）〔17〕 非 directVisible 的工具从可见数组移进 catalog，模型通过 tool_search → tool_describe → dispatch_action 使用；默认搜索 8，最多 20，硬上限 50；codemode 模式只暴露 exec/wait〔17〕〔32〕
Claude Code【bundle】 ENABLE_TOOL_SEARCH 支持 auto / auto:N / true / false，未设置时默认启用（tst）；不是 first-party 的 ANTHROPIC_BASE_URL 和 Vertex 会关闭 optimistic 路径；auto 模式的阈值是 上下文的 10%，算不出 token 数时改用字符数，阈值乘 2.5〔33〕〔34〕 已发现的工具从 tool_result 里的 tool_reference 提取，压缩后继承 preCompactDiscoveredTools；用 delta 记录新增和移除的工具〔35〕。【文档】加载前显示工具名和 server instructions（相关上限在 2.1.295/2.1.296 改过，不视为 2.1.197 的值）〔36〕

MCP 调用的权限： - OpenCode： 调用前执行 permission.assert〔19〕。 - Hermes： 对 trust: untrusted 的 server，只有 readOnlyHint 严格为 True 的工具免审批，其余先征求一次同意，审批出错就阻止〔18〕。 - pi： 项目信任只控制是否加载项目级 MCP 配置，不等于逐个工具的审批〔3〕。

对不同用户的影响（基于控制流的情景推演）

  • 重度用户、成本敏感用户： 接了 10 个 MCP server、几百个工具。Codex、Hermes、OpenClaw、Claude 默认都会延迟加载，pi 默认走 codemode；dsh 默认 native 全量声明，要手动切到 ptc。不切换的话，工具声明会持续占用上下文和缓存前缀〔12〕〔16〕〔17〕〔33〕〔14〕〔15〕。

  • 扩展作者： 加载后的调用方式不同，工具的可观测性也不同：

    • pi、Codex：加载后直接声明，模型像调用原生工具一样调；
    • Hermes、OpenClaw：一直经过 call/dispatch 桥。

    日志、权限规则和评测脚本看到的工具名会不一样〔29〕〔27〕〔31〕〔32〕。

  • 长任务用户： 加载过的工具在压缩后还在不在？pi-durable 明确保留，Claude【bundle】继承压缩前已发现的工具。其他家在所核路径上没有确认〔30〕〔35〕。

  • 企业团队： 超时默认值差异很大，从 dsh/pi 的 60s 到 OpenCode 的 12 小时。长时间运行的 MCP 工具在不同 harness 上会表现为“超时失败”或者“一直挂着”〔4〕〔3〕〔2〕。

面试可讲的点

  1. 工具多了怎么办： 各家已经趋同到“目录 + 检索 + 按需加载”。真正的产品决策是三件事：触发条件（总是 / 按阈值 / 按配置）、加载后的调用方式（原生声明还是桥接）、压缩后是否保留。
  2. 两类可度量的指标： 工具检索的命中率和“检索后首次调用成功率”；工具声明占用的上下文比例。
  3. 社区诉求： pi 用户要求兼容 Claude 的 .mcp.json 和 Stateless MCP；Claude 用户报告 MCP elicitation 被自动拒绝（见 15）。跨 harness 的 MCP 配置兼容是低成本、高收益的 roadmap 项。
