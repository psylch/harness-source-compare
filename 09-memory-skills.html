场景：客户经理周一告诉 agent“周报用中文、不要提旧客户”，周五新开会话。

〔基于代码的推演〕下表按所引快照描述；Claude Code 的文档或 bundle 证据单独标注。

Harness 从用户操作到结果
Codex 满足后台记忆筛选条件 → 两阶段生成和整理 → 按 feature 设置注入；不是每条纠正必然成为记忆。〔4〕〔5〕
OpenCode 发现 skill → 经权限读取正文；默认从纠正自动生成记忆未确认。〔9〕
pi 扫描技能目录 → 模型按需读正文；所核核心没有确认自动提炼这条偏好的闭环。〔6〕〔7〕
dsh 发现并监听 skill 文件 → 变化可被发现；监听不是自动从聊天学习。〔8〕
Hermes 显式写 MEMORY/USER → 下次构建 system 注入；当前冻结快照不立即变，预算分别 2200/1375 字符。〔3〕〔10〕
OpenClaw memory_search/get 检索 → promotion/dreaming 另有处理；默认周期与统一 TTL 未确认。〔12〕〔13〕
Claude Code 【bundle】按 MEMORY 的行数和字符预算加载 → 提示模型写记忆；不保证每次纠正都会写入。〔14〕〔15〕
DeepAgents（1 月 Python） 默认文件存在线程状态；配置 StoreBackend 可跨线程保存，CompositeBackend 按路径分流；仍需产品决定存什么、如何删除。deepagents@c177c9f:libs/deepagents/deepagents/backends/state.py#L28-L37；deepagents@c177c9f:libs/deepagents/deepagents/backends/store.py#L28-L58；deepagents@c177c9f:libs/deepagents/deepagents/backends/composite.py#L37-L45

为什么重要： 验收不是模型说“记住了”，而是下一次任务是否检索、采用并正确遗忘。存储、筛选、注入要分别有证据。

技术细节与出处

pi 的层次： agent-core 是循环与事件库；Bash、会话文件、自动压缩、技能和扩展等条目按引用归属 coding-agent；durable 是另一个持久运行时。下表的 10 月能力不能倒推为年初的库选型理由。

术语速读：step 是一次模型请求，turn 是一段任务；hook / middleware 是执行前后插入的业务逻辑；schema 是工具参数格式；checkpoint 是恢复检查点，journal 是已完成调用的结果日志；backend 是实际存储或执行后端；token 是模型计量文本的单位。

共识

  • 要转成模型可读内容才会生效：
    • pi：先给技能目录，再用 read 加载正文；
    • Codex：memory extension 把摘要放进 developer policy；
    • Hermes：把记忆快照放进 system〔1〕〔2〕〔3〕。
  • 文件在不等于被用上： 磁盘上有这个文件，不代表每次请求都读到了，也不代表自动学习闭环已经开启。

关键差异

Harness 持久内容与发现 自动学习、淘汰与边界
Codex memory_summary / MEMORY / raw / skills / rollout 摘要是 consolidation 模板里的约定，实际是否注入还要看 feature 和使用设置；skills 从配置层、CODEX_HOME/skills、用户 .agents/skills、系统/管理目录和祖先目录中发现〔4〕 有真正的两阶段后台记忆管线。前提条件包括非 ephemeral、MemoryTool 已启用、是 root thread 等。默认每次处理 2 个 rollouts，最大 age 10 天，最小 idle 6 小时，unused 30 天；phase1 并发 8，lease/retry 3600s。consolidation worker 自身禁用再学习、apps/MCP/plugins/collab；Managed 模式只写 memory root 并断网。模板允许 no-op〔5〕
pi coding-agent 递归发现 SKILL.md，目录里有 name/description 供按需读取；项目指令和技能是独立资源〔6〕 所核核心路径上未确认默认的自动记忆抽取或技能淘汰，扩展可以自己实现〔7〕
dsh skill-filesystem 从 .dsh/.agents、custom/user/bundled 几个根目录发现并 watch〔8〕 能确认动态发现，未确认“成功任务→写 skill→按使用率淘汰”的闭环；watch 文件不等于学习〔8〕
OpenCode 可配置 skill paths；discovery 支持 URL 索引和缓存；skill 工具按 ID 经过 permission 检查后才读正文〔9〕 未确认默认的自动技能生成或语义记忆淘汰〔9〕
Hermes MEMORY.md、USER.md 默认预算 2200 / 1375 chars，可配置；写盘和 system 冻结快照是分开的〔3〕〔10〕 curator 默认 enabled=true、consolidate=false；managed skills 按 active→stale→archived 流转，pinned 和被 cron 引用的受保护，归档后可恢复〔11〕
OpenClaw memory-core 注册 memory_search / get 和 private recall；standing intents 可以在用户触发时 prependContext〔12〕 有 short-term promotion / dreaming，记录成功、拒绝、失败的审计；默认调度频率和统一 TTL 未确认〔13〕
Claude Code【bundle】 auto-memory schema 描述了项目 memory 目录和 autoMemoryEnabled / autoDreamEnabled；MEMORY 加载限制 200 行 / 25000 JS string.length，不是 25000 UTF-8 bytes〔14〕 prompt 里确实有写记忆和技能的指导，但这只说明模型被这样指导过，不说明每次都会写；确定性的过期调度未确认〔15〕

对不同用户的影响（基于控制流的情景推演）

  • 重度用户： 周一纠正了测试命令，周三开新任务时会不会自动带上？Codex 要满足后台阶段的筛选并成功 consolidate 才可能带上；Hermes 显式写入的记忆可以跨会话带入，但当前会话的 system 仍是冻结的。验收要看下一会话能否正确检索，不能只看模型说了一句“已记住”〔5〕〔10〕。
  • 企业安全团队： 旧客户的规则不应该被永远继承。Codex 的 age / idle / unused 筛选和 Hermes 的技能归档是两种不同的治理方式，都替代不了企业自己的数据保留策略〔5〕〔11〕。
  • 扩展作者、非工程师： 装了一个“报表技能”之后，安装成功、被发现、获准读取、实际遵循是四个可以分别失败的环节。UI 不应该只显示一个“已安装”的勾〔6〕〔9〕。

面试可讲的点

  1. 把记忆拆成三个可度量的环节：写入率、检索命中率、注入后遵循率。
  2. 缓存和新鲜度之间有取舍：Hermes 冻结 system 保住缓存前缀，代价是新事实要通过对话或工具结果才能让模型知道〔3〕〔10〕。
  3. “编码类 harness 只靠指令文件”这个说法在 Codex 当前快照上不成立，它确实有自动 memory 生成〔5〕。
