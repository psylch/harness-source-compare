09 · 子 agent：独立上下文不等于独立文件系统

← 08 · 记忆与技能：存下来、选出来、再注入是三件事 · 总览 · 10 · 多 agent 策略：从 Kimi /tower 到各家编排 →

（多 agent 编排策略，如 Kimi /tower、/swarm、agent teams，见 10 · 多 agent 策略。本页只讲各 harness 内建子 agent 的默认值。）

共识

  • 子 agent 有独立的消息状态和生命周期，父 agent 拿到的是经过选择的结果，不是全部中间 token。例子：Codex 可选 fresh 或 full-history，dsh 区分 spawn 和 fork，OpenCode 新建或复用 child session〔1〕〔2〕〔3〕。
  • 这样设计是为了组织上下文、控制成本；工作区隔离是另一回事，要单独核对。

关键差异

Harness 创建、上下文与工具 回父路径与默认限制
Codex Fresh 或 FullHistory，创建参数里带 model / reasoning / type / fork 策略〔1〕〔4〕 V1 默认 children 6、depth 1；V2 默认 concurrency 4，含父 agent，子 agent 实际可用 slot 是 4−1。错误摘要上限 900 tokens，这个上限不适用于成功结果〔5〕
pi 只有示例 extension：spawn pi --mode json -p --no-session，可以传 tools 和 model〔6〕 示例里最多 8 tasks / 4 并发，output 50*1024 bytes。这些是示例常量，不是内建默认值〔7〕
dsh spawn 用 preset 和 output schema 开一个 fresh child；fork 只复制到上一个已完成的 turn，正在进行的 turn 不复制〔2〕〔8〕 默认 depth 1、active 8；深度取持久信息中的约束〔9〕
OpenCode fresh child 默认不复制父 history，可以通过 sessionID 复用；可以前台等待，也可以后台返回 ID〔3〕 默认 depth 1，experimental.subagent_depth 可调；完成时用一条含 sessionID/state 的 synthetic 消息加最后一条 assistant text 回父，notificationID 去重〔10〕
Hermes 新建一个 AIAgent，skip_context_files 和 skip_memory 为 true，clarify=None；工具取父 agent 工具集的交集，再剔除 blocked 的〔11〕 默认 concurrent 10、depth 1、timeout=None；设了正的 timeout 时下限 30s〔12〕
OpenClaw subagent prompt 把继承来的 history 标为 background，当前任务单独列出〔13〕 每个控制会话默认 concurrent 8，每父 maxChildren 5，depth 5，archiveAfter 60 分钟〔14〕
Claude Code【bundle】 child 有新的 messages 和 readFileState，可以选 fork；Explore / Plan 会删掉 gitStatus；工具过滤保留 MCP，并应用 allowed/disallowed〔15〕 depth<5 时才保留 Agent 工具；maxTurns 可以由调用方或 agent definition 传入〔16〕

对不同用户的影响（基于控制流的情景推演）

  • 长任务用户、成本敏感用户： 同时让 5 个 agent 查 5 个模块。Codex V2 默认 4 个 slot 含父，所以不会有 5 个 child 同时跑；pi 示例并发 4；Hermes 默认 10。实际吞吐还取决于 provider 限流和结果长度〔5〕〔7〕〔12〕。
  • IDE 用户： 父 agent 刚读到失败的测试，接着 fork 一个去调试。dsh 的 fork 只复制到上一个完成的 turn，所以这份失败证据要显式写进 child 的任务里〔8〕。
  • 企业团队： Hermes 默认不给 child 注入个人记忆和项目文件，并收窄工具集。这降低了意外继承的风险，但父 agent 必须把交付规范写进任务〔11〕。

面试可讲的点

  1. 默认上下文是一个隐性的成本杠杆：fresh、fork 到上一完成 turn、full history，三种选择的 token 成本和遗漏风险不同。
  2. 并发上限要问清是否含父、是按会话算还是按父 agent 算（OpenClaw 的 8 和 5 是两个不同的约束）〔14〕。
  3. 子 agent 的“结果合同”（返回格式、长度上限、错误摘要）大多没有统一，这是 roadmap 可以补的地方。
