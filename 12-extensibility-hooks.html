共识

  • 扩展点集中在四类位置： 工具前后、模型请求前、上下文构造、生命周期事件。

    • pi：tool_call / tool_result；
    • Codex：PreToolUse；
    • OpenCode：execute.before / after；
    • Hermes：middleware。

    共同目的都是把业务策略插在副作用和模型之间〔1〕〔2〕〔3〕〔4〕。

  • 决定实际权限的是三件事： 能改什么、改完是否重新校验、出错时 fail-open 还是 fail-closed。

关键差异

Harness 工具参数、拦截与结果 system / loop / UI 层面
Codex PreToolUse 中任何一个 block 都优先；否则取最后完成的 hook 给出的 updated_input。PermissionRequest 可以 allow/deny，任一 deny 优先，不能替换参数〔2〕〔5〕 内部 Rust extension API 可以贡献 MCP/plugin 和 developer policy/context fragments；model request metadata 不能覆盖已有 key；tool lifecycle 对最终 payload 只读〔6〕
pi extension 的 tool_call 可以改 input，类型注释明确说不重新校验；tool_result 可以改 content/details；pi-durable 的 tool hook 之后会重新 validate〔1〕〔7〕 before_agent_start 可以改 system；UI 有 select/input/editor/raw terminal 接口；底层 Agent 可以 transformContext、prepareRequest、finishTurn〔8〕
dsh pre hook 可以 allow/deny/ask/cancel；around execute 只能改 signal，args 冻结；post hook 可以 replace/enrich/block〔9〕 system assembly 有 hook，但最终 sections 会恢复；generation request 冻结。setFactory 可以安装一个 agent factory，是真正能替换 loop 的入口，同时只能有一个 provider〔10〕
OpenCode execute.before 可以改 name/input、可以 block；after 可以改 result/error〔3〕 session hook 可以改 context/system/messages/tools 和 compaction；在请求 hook 里凭空造出来的 tool schema 不会生成执行器，没注册 executor 的会被丢弃〔11〕
Hermes middleware 可以改 args 或 block；追踪被插件改过的 args，对 ACP 的修改 fail-closed；pre-tool hook 超时 fail-closed，其他 observer 通常 fail-open〔4〕〔12〕 plugin 提供的 system sections 会冻结进 prompt〔13〕
OpenClaw before_tool_call 可以改 params、block、requireApproval〔14〕 beforePromptBuild 可以替换 system、context、toolsAllow；API 有 registerControlUiDescriptor、registerContextEngine、registerAgentHarness〔15〕
Claude Code 【bundle】SDK 的 canUseTool 可以返回 updatedInput，并重新 validate〔16〕；【文档】Mods 的 tool.check 在 rules/settings hooks 之后介入〔17〕 【文档】Mods 可以加 UI、改 prompt/tool，turn.step 能控制下一次是调模型还是直接无 LLM 回复；不能改变 permission prompt 的显示；默认启用要求 CLI 2.1.287 / Desktop 2.1.286，不能据此认定 2.1.197 已有同等能力〔18〕

MCP 的边界： MCP 可以远程提供 schema 和执行服务，但不会自动获得修改宿主 system、loop 或 UI 的权力。详见 07 · MCP 与工具接入〔19〕。

对不同用户的影响（基于控制流的情景推演）

  • 扩展作者： 想给所有写文件工具自动加企业目录前缀。Codex 用 PreToolUse 可以，用 PermissionRequest 不行；pi CLI 改完不重新校验，pi-durable 会重新校验；dsh 的 around 做不到改参数。选错 hook，就会出现运行时漏控或 schema 不合法〔2〕〔5〕〔1〕〔7〕〔9〕。
  • 企业团队： 安全检查服务超时了。Hermes 的 pre-tool hook 会阻断，但普通 observer 失败会放行。配置里要标清楚一个扩展是强制门禁还是尽力记录〔12〕。
  • 重度用户、成本敏感用户： 想把“查缓存，命中就直接答”放在模型调用之前。只有 loop 级的控制（pi 的 finishTurn/prepareRequest、dsh 的 setFactory、Claude Mods【文档】的 turn.step）才能真正省掉这次请求；靠 tool 查缓存仍然要先调一次 LLM〔8〕〔10〕〔18〕。

面试可讲的点

  1. “开放度”看的是具体合同：可变性、重新校验的时机、失败策略，不是插件数量。
  2. 扩展 API 正在成为生态之争的焦点：Claude Mods 发布后，dsh 很快做了兼容层。社区信号见 15。
  3. 业务表单和安全审批是两种扩展权限，Claude Mods 文档明确保护了审批的显示〔18〕。
