共识（框架骨架）

把这句话拆成三个维度，外加一条护栏： - 更多的人（Reach） - 更多场景（Breadth） - 更深入（Depth） - 真的帮到（Outcome） - 护栏：信任（Trust），深度提升不能以牺牲信任为代价。

北极星候选：每周“有效深度委托”数。 定义为同时满足以下四个条件的任务数：达到自主时长或步数阈值；已完成；结果被采纳；没有回滚。再按用户和场景去重。 拆解时用任务意图分类 × 用户分群做矩阵，看增长到底来自更多的人、更多场景，还是更深。

更多的人 周活“有效 agent 用户”（每周至少有 N 个完成并被采纳的任务）；非工程师占比；D7/D28 留存 04 审批与隔离、13 扩展性 默认权限档位；审批弹窗频率；非工程师能看懂的状态 UI

对不同用户的影响（分群建议）

  • 重度长任务用户： 主看“更深入”和“恢复”，护栏是压缩后的失败率。
  • 非工程师： 主看“更多的人”和首次成功率，护栏是误批准率和“已收到/已开始”状态被误解导致的重复提交（见 02）。
  • 企业团队： 主看信任护栏和审计（扩展是强制门禁还是尽力记录，见 13）。
  • 成本敏感用户： 主看每个被采纳任务的成本。注意口径：Hermes 的 attempt 含首次、pi 的 retry 不含首次，跨产品比较前要先统一（见 02）。

面试可讲的点

  1. 实验设计： 用灰度加 A/B 测 harness 改动，比如压缩阈值、截断方向、默认权限档位、子 agent 默认上下文。主指标选采纳率，护栏选回滚率和干预次数。
  2. 埋点要对准 harness 边界： steer 入队、被采纳、工具开始/结束、压缩触发、checkpoint 提交、恢复，每个边界一个事件，才能把指标变化归因到具体的层。
  3. “有效”要用采纳来定义，不用打开次数。 防止只在少数场景里把使用量刷高。
  4. 多 agent 的专项指标： gate 首次通过率、review 轮数、每个 mission 的 token、resume 比例、scope 越界被拒次数（见 11）。
