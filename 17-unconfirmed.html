17 · 证据边界：未能在代码中确认的点

← 16 · 面试可讲的 8 个细节 · 总览 · Agent Harness 源码对比 · 面试精简版 →

“未确认”的意思是这次的源码证据不足，不能读成“产品不支持”。

共识

  • 数字的口径： 所有数字都是所列路径上的默认值或常量，多数可以配置。
  • 用户情景的性质： 是从源码控制流推演出来的，没有跑过跨产品的同任务 bench、故障注入或缓存账单测量，所以不能当作延迟或成功率排名。

  • Claude Code 有两个证据时点：

    • 【bundle】是 2.1.197 二进制里的字符串；
    • 【文档】是 2026-10-18 抓取的官方文档，部分描述的是更新的版本：AGENTS.md 直接读取需要 2.1.277+，Mods 默认启用需要 CLI 2.1.287+，idle compaction 需要 2.1.290+。

    文档里的能力不能反推到 2.1.197〔1〕。

关键差异：各家未确认项

Harness 未确认点
Codex 统一的数值 max-steps；所有工具的统一并发上限；通用的输入 requestId 去重和外部 exactly-once；普通安装的插件能否完整替换 loop/UI〔2〕
pi 普通 agent 的统一 max-steps 和工具并发上限；默认的自动个人记忆学习与过期；示例之外的内建 subagent 限制；durable 自定义 adapter 的介质级承诺；JSONL 每个 main commit marker 是否都 fsync〔3〕
dsh 主 loop 的统一 maxSteps；edit 的模糊 fallback；默认的自动记忆/技能学习闭环；所有 subagent provider 的返回格式；第三方 UI 合同〔4〕
OpenCode 所核 shell 的默认 OS 沙箱；tool 和 child 的全局数值并发上限；统一的默认 SQLite 文件名；CLAUDE.md 自动 fallback；自动记忆淘汰；公开插件能否整体替换 runner/UI〔5〕
Hermes 统一的图片尺寸/字节默认值；child 结果在每个分支下的精确包装；公开插件能否整体替换 loop/UI；任意崩溃的工具能否自动续跑〔6〕
OpenClaw 跨 embedded/native harness 统一的 max-steps、并发上限、工具收窄和子结果合同；memory dreaming 的默认调度周期和统一 TTL；所有 provider 的缓存 breakpoint 和计量算法〔7〕
Claude Code 2.1.197 主线程固定的 maxTurns；跨 provider 的 reasoning 映射；完整的 PTY 和跨命令环境恢复；统一的图片上限；自动记忆的确定性 expiry；全部 child 结果格式；跨进程 writer 锁；端到端外部幂等〔8〕
横向 远程模型服务内部的压缩、服务端缓存命中、网络 effect 的保证，都不在本地源码能证明的范围内

对不同用户的影响

引用这些未确认项时，统一说“未在所核路径确认”，不说“没有”。面试中被追问时，可以说明证据来自哪个快照、哪条路径。

面试可讲的点

  1. 把“我知道什么、证据在哪、哪里还不确定”分开说，本身就是 harness PM 需要的能力。
  2. Claude 的版本门槛就是一个现成的例子：同一个能力在文档里存在，不代表在某个已安装的版本里存在。
