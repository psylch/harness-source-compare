一句话：循环骨架高度收敛，执行语义远未收敛。 “生成→工具调用→结果回填→继续/结束”各家几乎一样；真正改变长任务体验的是：插话在哪个边界生效、哪些工具能同时跑、截断留下哪一端、压缩保留什么、进程消失后恢复的是聊天记录、工作队列还是脚本执行状态。

版本快照： Codex ce0323f · OpenCode 8c173a8 · pi c268154 · DeepSeek Harness（dsh）687f282 · Hermes 18c525b · OpenClaw 21de16f · Claude Code 2.1.197（闭源）。Claude 条目标注来源：【bundle】= 二进制内字符串，【文档】= 官方文档（厂商说法，且部分描述的是比 2.1.197 更新的版本）。数字均为所列路径的默认值，多数可配置。

1. Agent loop：插话的生效边界

  • 共识： 把工具调用和面向人的回答分开，工具结果变成下一次请求的输入；工具边界也是取消、审批、恢复插入的位置。
  • 最能说明差异的例子： “支持 steer”在各家含义不同。pi、Hermes 在工具批次结束后才把插话交给下一次请求；dsh 拆成三种：steer=下一 step 并唤醒，followup=下一 turn 并唤醒，inject=下一 step 但不唤醒，next-step 整批取、next-turn 最多取一条；Codex 在 sampling 之后处理 pending input。〔pi@c268154:packages/agent/src/agent-loop.ts#L294-L328；hermes-agent@18c525b:agent/agent_runtime_helpers.py#L3758-L3792；deepseek-harness@687f282:packages/core/agent-loop/src/inbox.ts#L20-L65；codex@ce0323f:codex-rs/core/src/session/turn.rs#L589-L604〕
  • 重试计数同样不能直接比： Hermes 默认 3 是 attempts（含首次）；pi 默认 retry 3、起始 2000ms，是失败后的额外尝试；Codex stream 5 / request 4，传输从 WebSocket 降到 HTTPS 后会重置计数。〔hermes-agent@18c525b:agent/agent_init.py#L1441-L1452；pi@c268154:packages/coding-agent/src/core/settings-defaults.ts#L18-L25；codex@ce0323f:codex-rs/model-provider-info/src/lib.rs#L67-L75〕
  • PM 结论： 插话不等于撤销，批次里已写的文件不会回滚。UI 要把“已排队 / 下一步采纳 / 停止当前执行”分开显示。

2. 工具并发：并行的资格与冲突域

  • 共识： 工具调用都经过声明→校验→授权/拦截→执行→模型可见结果；“并行”都带顺序约束。
  • 差异例子： 模型一次发出三个工具调用。Codex 让 parallel-safe 调用共享读锁、其他调用独占写锁（64 是存活 unified-exec 进程上限，不是工具线程数）。pi 默认并行，但批次里只要有一个工具声明 sequential，整批串行。Hermes 按路径冲突划出串行屏障，worker 上限 8。dsh 要求工具显式声明 isConcurrencySafe 才进并行池，默认 10。Claude【bundle】把连续的 concurrency-safe 调用分组并行，默认上限 10。〔codex@ce0323f:codex-rs/core/src/tools/parallel.rs#L205-L233；pi@c268154:packages/agent/src/agent-loop.ts#L508-L523；hermes-agent@18c525b:agent/tool_executor.py#L133-L136；deepseek-harness@687f282:packages/core/agent-loop/src/constants.ts#L5-L6；【bundle】claude-code@2.1.197:bundle-split.js#L664199-L664249〕
  • PM 结论： 同一模型、同样三次调用，耗时和文件竞争风险可以不同。“支持并行”要拆成耗时、结果排序、冲突控制三个问题来问。

3. 审批与 OS 隔离：两道不同的边界

  • 共识： 都有“是否允许执行”的审批层。
  • 差异例子： 用户点了“允许运行 npm”之后，进程能看到什么？Codex 在 Linux 上走 bubblewrap+seccomp；dsh 在 Linux 上依次尝试 bwrap、Landlock，macOS 用 Seatbelt，Windows 用 ACL；pi 默认 shell 直接在本机 spawn；OpenClaw sandbox 默认 off（启用后默认 docker、workspaceAccess none）；Hermes 默认 local backend。〔codex@ce0323f:codex-rs/linux-sandbox/src/lib.rs#L1-L5；deepseek-harness@687f282:packages/sandbox/sandbox-local/src/index.ts#L142-L181；pi@c268154:packages/coding-agent/src/core/tools/bash.ts#L97-L136；openclaw@21de16f:src/agents/sandbox/config.ts#L221-L231；hermes-agent@18c525b:tools/terminal_tool.py#L1-L6〕
  • PM 结论： 不能给产品贴一个永久的“有沙箱”标签。比较部署时要记下实际启用的 backend/profile。

4. 工具输出截断：留哪一端、用什么单位

  • 共识： 长输出都会截断，全文多数另存。

  • 差异例子： 同一份测试日志（开头是配置，中间是失败，结尾是汇总）：

    • pi：2000 行或 50KiB，bash 留尾，全文存临时文件；
    • Codex：unified exec 默认 10000 估算 tokens，进程缓冲 1MiB，头尾各半；
    • Hermes：max_bytes 默认 50000，但实际按字符切，头 40% / 尾 60%；
    • Claude【bundle】：Bash 默认 30000 字符留头，TaskOutput 32000 留尾。 〔pi@c268154:packages/coding-agent/src/core/tools/truncate.ts#L11-L13、pi@c268154:packages/coding-agent/src/core/tools/bash.ts#L255-L255；codex@ce0323f:codex-rs/core/src/unified_exec/mod.rs#L68-L77、codex@ce0323f:codex-rs/core/src/unified_exec/head_tail_buffer.rs#L5-L19；hermes-agent@18c525b:tools/tool_output_limits.py#L13-L54、hermes-agent@18c525b:tools/tool_output_truncate.py#L12-L32；【bundle】claude-code@2.1.197:bundle-split.js#L624367-L624375、claude-code@2.1.197:bundle-split.js#L657987-L657993〕

  • PM 结论： “模型忘了报错”有时是截断策略的问题，不是推理能力的问题。这是可以 A/B 的 harness 参数。

5. 上下文与压缩：触发公式各不相同

  • 共识： 都用最近一次 provider usage 加上新增内容的本地估算来判断空间，空间不足时摘要较早部分。

  • 差异例子（W=窗口）：

    • pi：W−16384 触发，保留近期约 20000 tokens；pi-durable 另在 W−16384−32768 提前后台摘要；
    • OpenCode：buffer=max(floor(0.1W), W≥32000 时取 16000)，保留近期 15000；
    • dsh：floor(min(0.8W, W−reservedCompletion−65536))；
    • Hermes：基础阈值 0.50，窗口 <512000 时至少 0.75；
    • Claude【bundle】：W−min(maxOutput,20000)−13000；
    • Codex：auto-compact 上限 W×9/10，并按 provider 能力分 remote / local 两条路径。

    代入 W=200K：pi 约 183.6K 触发，OpenCode 180K，Codex 不高于 180K，Claude（maxOutput≥20000 时）167K。〔pi@c268154:packages/coding-agent/src/core/compaction/compaction.ts#L267-L269；pi@c268154:packages/durable/src/harness/generation.ts#L327-L337；opencode@8c173a8:packages/core/src/session/compaction.ts#L906-L917；deepseek-harness@687f282:packages/compaction/compaction-basic/src/config.ts#L172-L197；hermes-agent@18c525b:agent/context_compressor.py#L2760-L2816；【bundle】claude-code@2.1.197:bundle-split.js#L556251-L556328；codex@ce0323f:codex-rs/protocol/src/openai_models.rs#L520-L540〕

  • PM 结论： “接近上限就总结”预测不了第 90 分钟还剩什么。用户真正关心的是：刚发现的失败证据能否原样读回，摘要什么时候生效。

6. 记忆：存下来、选出来、再注入是三件事

  • 共识： skill 和记忆都要转成模型可读的内容才生效。技能目录加按需读取正文，是各家通用的做法。
  • 差异例子： Codex 有真正的两阶段后台记忆管线：默认每次处理 2 个 rollouts，最大 age 10 天，最小 idle 6 小时，unused 30 天，phase1 并发 8，lease 3600s。Hermes 是显式写 MEMORY.md / USER.md（默认 2200 / 1375 chars），写盘后当前会话的 system 快照保持冻结，curator 默认 enabled 但不自动 consolidate。pi、dsh、OpenCode 在所核路径上只确认了技能发现，没确认自动学习。〔codex@ce0323f:codex-rs/memories/write/src/start.rs#L20-L91；codex@ce0323f:codex-rs/config/src/types.rs#L55-L60；hermes-agent@18c525b:tools/memory_tool_store.py#L222-L253、hermes-agent@18c525b:tools/memory_tool_store.py#L618-L621；hermes-agent@18c525b:agent/curator.py#L106-L148〕
  • PM 结论： “已记住”不等于下一次请求的 system 已更新。验收要看下一会话能否正确检索到。

7. 子 agent：独立上下文不等于独立文件系统

  • 共识： 子 agent 有独立的消息状态，父 agent 只拿到选择过的结果。

  • 差异例子： 让 5 个 agent 同时查 5 个模块：

    • Codex V2 默认 4 个 slot 且含父（V1 是 6 children / depth 1）；
    • Hermes 默认并发 10、depth 1；
    • dsh 默认 active 8、depth 1；
    • OpenClaw 每控制会话并发 8、每父 5 个、depth 5；
    • pi 只有示例 extension：8 tasks / 4 并发。

    dsh 的 fork 只复制到上一个已完成的 turn，父 agent 刚读到的失败证据不会进入 child。〔codex@ce0323f:codex-rs/core/src/config/mod.rs#L255-L266；hermes-agent@18c525b:tools/delegate_tool_config.py#L17-L27；deepseek-harness@687f282:packages/subagent/subagent/src/index.ts#L187-L197；openclaw@21de16f:src/config/agent-limits.ts#L19-L45；deepseek-harness@687f282:packages/subagent/subagent-fork-in-process/src/index.ts#L40-L77〕

  • PM 结论： 并发数字只决定调度是否可行，吞吐还受限流、共享工作区和结果长度影响。

8. 持久化与恢复：保证要落在失败窗口上

  • 共识： 各家都保存有序状态，但每家要防的失败窗口不同。

  • 差异例子：

    • dsh：在调用 LLM、顶层 tool 和 pre-step 之前 flush checkpoint，失败就不继续；用 POSIX flock / Windows semaphore 做跨进程写者锁；
    • Codex：rollout 写入只 flush 不 fsync，daemon handoff 后做 cold resume；
    • OpenCode：SQLite inbox，restart 默认 10 次，at-least-once；
    • Hermes：执行 tool call 前先 flush，lease 每 60s 刷新；
    • pi-durable：没有跨进程锁，由宿主保证 single writer。 〔deepseek-harness@687f282:packages/session/session-checkpoint-policy/src/index.ts#L52-L82、deepseek-harness@687f282:packages/session/session-persistence-jsonl/src/lease.ts#L70-L115；codex@ce0323f:codex-rs/rollout/src/recorder.rs#L1915-L1915、codex@ce0323f:codex-rs/app-server/src/daemon_thread_recovery.rs#L30-L49；opencode@8c173a8:packages/core/src/session/execution/restart.ts#L23-L61；hermes-agent@18c525b:agent/turn_tool_round.py#L130-L150；pi@c268154:packages/durable/README.md#L688-L688〕

  • PM 结论： 与其问“有没有 resume”，不如问“外部操作成功、结果还没提交时崩溃怎么办”，这个问题更有区分度。

9. 扩展性：能看到 ≠ 能改，能改请求 ≠ 能换 loop

  • 共识： 扩展点都集中在工具前后、请求前、上下文构造和生命周期事件。

  • 差异例子： 想给所有写文件工具自动加企业目录前缀：

    • Codex：PreToolUse 能改 updated_input，PermissionRequest 不能改参数；
    • pi：CLI 的 tool_call 能改 input 但不重新校验，pi-durable 改完会重新 validate；
    • dsh：around hook 只能改 signal，args 冻结；但 setFactory 可以整个替换 loop；
    • OpenClaw：可以 registerAgentHarness；
    • Claude Mods【文档】：能控制 turn.step 和 UI，但不能改 permission prompt 的显示；默认启用要求 CLI 2.1.287。 〔codex@ce0323f:codex-rs/hooks/src/events/pre_tool_use.rs#L115-L166、codex@ce0323f:codex-rs/hooks/src/events/permission_request.rs#L1-L15；pi@c268154:packages/coding-agent/src/core/extensions/types.ts#L1250-L1255；pi@c268154:packages/durable/src/harness/tool.ts#L143-L161；deepseek-harness@687f282:packages/core/tools/src/index.ts#L145-L177、deepseek-harness@687f282:packages/core/agent/src/index.ts#L349-L368；openclaw@21de16f:src/plugins/plugin-api.types.ts#L377-L389；【文档】claude-code-docs:plugins_mods_overview.md#L68-L115〕

  • PM 结论： 真正的“开放度”看这些具体合同，不看插件数量。

哪些不值得当差异讲

以下几点各家基本相同，单独拿出来讲区分度不高： - 循环骨架：生成、提取工具调用、执行、回填； - 工具结果回填给模型； - 用“最近一次 usage 加尾部 chars/4 估算”来计量上下文； - 先给技能目录、再按需读正文。

面试可讲的 8 个细节

  1. 插话边界： steer 是在当前工具前、工具批后，还是下一 turn 生效？pi/Hermes 在批后；dsh 把 next-step、next-turn、wake 拆开。
  2. 并行的资格： Codex 用读写锁；pi 一个 sequential 就让整批串行；Hermes 按路径冲突划区段。
  3. 截断的方向和单位： pi bash 留尾，Codex 头尾各半，Hermes 字段叫 max_bytes 实际按字符切。“工具成功了却没看见失败日志”的根因常在这里。
  4. 压缩公式： pi W−16384；OpenCode 有 16000 的 buffer floor；Claude 另扣输出预算再减 13000；Codex 还分 remote / local。
  5. 审批与隔离是两回事： 同样点了“允许”，Codex Linux bwrap/seccomp、pi 本机 spawn、OpenClaw 默认关沙箱，进程能看到的文件和系统能力完全不同。
  6. 跨会话学习是一条运行管线，不是一个文件名： Codex 有带筛选、lease 和隔离 worker 的两阶段生成；Hermes 有预算、冻结快照和 curator。
  7. 恢复的单位： dsh 日志 checkpoint、Codex cold resume、pi-durable 的 task 加 codemode journal，三者可以叠加，但互相替代不了。
  8. 扩展的变更权与失败策略： 哪个 hook 能改参数、改完重不重校验、超时后是 fail-closed 还是 fail-open（Hermes pre-tool 超时会阻断，普通 observer 失败则放行）。〔hermes-agent@18c525b:hermes_cli/plugins.py#L1874-L1880〕

pi-durable 一段话

pi-durable 把对话、任务和程序内的可记录调用放进同一套提交与恢复规则，形成一条可检查的恢复链： - Storage： 原子 commit，返回 Seq； - task： 重启时 running 的 task 改回 pending，保留 checkpoint； - 工具： 先提交 intent（{phase:execute}，默认 replay=unsafe）再真正执行。恢复时只有持久策略和当前策略都是 safe 才重跑，否则返回 interrupted； - codemode： 用 seeded PRNG 和虚拟时钟，nested call 的结果先写 journal 再投递，重跑脚本时复用已完成的结果。

边界同样明确： - requestId 只做同 conversation/type 的入队去重，不等于外部操作 exactly-once； - 没有跨进程写者锁； - SQLite 用 WAL / synchronous NORMAL，JSONL 默认 fsync=false，进程崩溃和断电要分开测试。

它最适合进程寿命短于任务、一个工具内部含很多调用的场景。〔pi@c268154:packages/durable/src/types.ts#L1047-L1064；pi@c268154:packages/durable/src/harness/scheduler.ts#L291-L310；pi@c268154:packages/durable/src/harness/tool.ts#L132-L192；pi@c268154:packages/durable/src/codemode/codemode.ts#L956-L1000；pi@c268154:packages/durable/src/harness/submissions.ts#L169-L188；pi@c268154:packages/chord/src/sqlite/node.ts#L189-L190；pi@c268154:packages/durable/src/storage/jsonl/storage.ts#L257-L307〕
